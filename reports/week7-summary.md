## **Week 7 report — Web Traffic Analysis, Enumeration & Vulnerability Testing**

### **Lab Environment**

* **Analyst VM:** Ubuntu Desktop (`10.0.0.10`)
* **Target Host:** Metasploitable2 (`10.0.0.20`)
* **Network:** Isolated VirtualBox internal network (no external connectivity)
* **Primary Tools:** `tcpdump`, Wireshark, `nmap`, `whatweb`, Nikto, browser-based testing (DVWA)

---

## **HTTP Traffic & Packet Analysis**

**Focus:** Network visibility and understanding web traffic at the packet level.

**Activities Completed:**

* Captured live HTTP traffic using `tcpdump`
* Analyzed request and response flows generated by web application interaction
* Identified:

  * HTTP request methods (GET, POST)
  * Headers, cookies, and form parameters
  * Server responses and status codes
* Practiced isolating application-layer data within TCP streams using Wireshark

**Key Takeaways:**

* Clear correlation between browser actions and packet-level traffic
* Improved familiarity with HTTP structure and session behavior

---

## **Web Enumeration & Fingerprinting**

**Focus:** Reconnaissance and attack surface identification.

**Tools & Results:**

* **Nmap HTTP scripts**

  * Identified supported HTTP methods
  * Enumerated exposed directories and applications
  * Observed server banner information
* **WhatWeb**

  * Fingerprinted Apache 2.2.8, PHP 5.2.4, Ubuntu
  * Identified WebDAV support
* **Wappalyzer**

  * Confirmed backend technologies and extensions
* **Nikto**

  * Detected multiple issues, including:

    * Outdated Apache version
    * Missing security headers
    * Enabled TRACE method
    * Exposed directories (`/doc`, `/test`, `/icons`)
    * Accessible phpMyAdmin instance
    * Sensitive files such as `phpinfo.php`

**Key Takeaways:**

* Legacy software and misconfigurations significantly expand the attack surface
* Enumeration tools complement each other when validating findings

---

## **Web Vulnerability Testing (DVWA)**

**Focus:** Hands-on interaction with common web vulnerabilities in a controlled lab.

### **Command Injection (Low Security)**

* Exploited unsanitized user input in the Command Execution module
* Injected OS commands using shell metacharacters
* Confirmed command execution under the `www-data` context
* Captured and analyzed full HTTP POST requests and responses via `tcpdump`

### **Directory Traversal / Local File Inclusion**

* Identified file inclusion through URL parameter manipulation
* Successfully retrieved:

  * `/etc/passwd`
  * System log files (`dmesg`, `messages`)
* Observed permission-based access failures for protected files (e.g., Apache logs, application configs)
* Distinguished between:

  * Presence of a vulnerability
  * Operating system–level access controls

**Key Takeaways:**

* Partial access and error responses still indicate exploitable conditions
* Web vulnerabilities are constrained by underlying OS permissions
